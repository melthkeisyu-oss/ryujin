# 毎年の作り直し手順

研修は**年度ごとに作り直す**。新しい年度は、前年度の台本を土台に「変わったところ」だけを書く。

## 年間スケジュール
| 時期 | やること | 見るところ |
|---|---|---|
| **12月下旬** | 前年度の「障害者虐待事例への対応状況等（調査結果）」が公表される → `facts` の数字を差し替える | 厚生労働省「障害者虐待防止法」のページ |
| **報酬改定の年の1〜3月**（次は令和12年度改定） | 改定の告示・通知・Q&Aが出る → 減算・基準のスライドを確定版にする | 厚生労働省「障害福祉サービス等報酬改定」、指定権者（埼玉県・沖縄県など）の集団指導資料 |
| **3月** | 新年度フォルダを作って生成し、登坂さんが内容を確認 | ― |
| **4月** | 受講ページを職員に配る（新規採用者は採用時にも受講） | ― |
| **年に1回** | 研修の記録（受講者・得点・日付）を、委員会の議事録と一緒に保存 | ― |

## 新しい年度を作る手順（例：令和10年度）
1. `facts/R9.json` をコピーして `facts/R10.json` を作り、年度名・数字・確認日を直す
2. `content/R10/` を作り、各研修について次のように書く
   ```json
   {"base": "R9/01_gyakutai", "review_note": "…", "slide_ops": [
     {"op": "replace", "heading": "古いスライドの見出し", "slide": { …新しいスライド… }},
     {"op": "insert_after", "heading": "このスライドのあとに", "slides": [ … ]},
     {"op": "delete", "heading": "いらなくなったスライドの見出し"}
   ]}
   ```
   変更が多い年は、`base` を使わずに台本を丸ごと書いてもよい
3. `python build.py R10 --dry` で長さを確認（8〜10分が目安）
4. `python build.py R10` で生成
5. 動画を一度通して見て、読み間違いがあれば `READINGS` に足して作り直す
6. 各スライドの数字・基準を、`sources` の資料で確認し、`checked`（確認日）を更新する
