# 公開前チェックリスト

公開ボタンを押す前に上から確認する。1つでも No があれば直す。

## 中身

- [ ] 記事のメッセージは **1つ** に絞れているか（2つあるなら記事を分ける）
- [ ] 自分が実際にやったこと（一次情報）が入っているか
- [ ] **失敗・つまずき**を書いたか（成功だけの記事は薄く見える）
- [ ] 数字が入っているか（時間・回数・金額・件数）
- [ ] 固有名詞で書いたか（「AIツール」→「Claude Code」）
- [ ] 読者が明日そのまま試せる手順 / コード / 設定があるか

## 読まれ方

- [ ] 1行目から結論・読者メリットになっているか（挨拶・前置きは削除）
- [ ] 見出しは 4〜6個あるか（スマホでは見出しが目次代わり）
- [ ] 1段落は3行以内か
- [ ] 見出しだけ拾い読みして内容が分かるか
- [ ] 一番言いたいことが記事の後半に埋もれていないか

## スキが押される導線

- [ ] 最後に問いかけ or 呼びかけを置いたか
- [ ] タイトルで「読むと何が得られるか」が分かるか
- [ ] ハッシュタグ 3〜5個を設定したか
- [ ] 見出し画像を設定したか

## 公開後（ここをやらないと伸びない）

- [ ] 同じテーマの他の人の記事を数本読んでスキ / コメントする
- [ ] 1週間後にビュー数・スキ数を記録して、次の記事の仮説にする

---

## 運用の原則

1. **頻度 > 完璧さ**。週1本を3ヶ月。渾身の1本より確実に伸びる。
2. **文字数は目的ではない**。上のチェックを通すと自然に 2000〜3000字になる。
   字数を稼ぐために薄い説明を足すのは逆効果。
3. **書けないときはテーマが広すぎる**。もう一段狭くする。
