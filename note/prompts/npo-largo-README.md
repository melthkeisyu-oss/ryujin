# npo-largo WordPress 自動投稿ルーティン

`https://npo-largo.com`（WordPress + SANGO + AIOSEO）に毎朝SEO記事を下書き投稿し、
30分後に品質チェックと自動修正をかける2本立てのルーティン。

| ルーティン | 実行時刻(JST) | 役割 |
|---|---|---|
| npo-largo 朝7時 福祉SEO下書き+アイキャッチ自動生成 | 毎日 07:00 | 記事執筆 → draft投稿 → アイキャッチ生成 → AIOSEO設定 |
| npo-largo SEO QA自動修正+合格時のみ公開(朝7:30) | 毎日 07:30 | 直前の下書きを検査・補修し、**公開ゲート13項目を全部満たしたときだけ公開** |

7:00 の作成側は `status: "draft"` 固定。公開の判断は 7:30 の QA 側だけが持つ。

## 公開フロー（2026-09-07 変更）

```
07:00  記事を書いて draft で保存 + アイキャッチ生成
07:30  QA が検査・自動補修
         ↓
       公開ゲート13項目を実データで判定
         ↓
   全部✓ → publish（公開URLを報告）
   1つでも× → draft のまま据え置き、理由を報告
```

公開ゲートは SEO 項目に加えて **項目12「事実の安全性」** を含む。
金額・割合・上限額・期間・年度・支給要件などのうち、確信を持って正しいと
言えない記述が1つでも残っていれば公開しない。迷ったら削る／公開しない、が原則。

対象は **その日に作成された下書き1件のみ**。過去日付の下書きには触れないので、
ゲートを通らずに残った記事が後日ひとりでに公開されることはない。

## 2026-08-22 改訂で追加した内容

### 多角的SEO（7観点）
1. **検索意図の特定** — Know / Do / Go / Buy を判定し、構成をそれに合わせる
2. **共起語の網羅** — 8〜12語を洗い出して本文に織り込む
3. **サジェスト想定質問を見出しに** — 「〜とは/条件/費用/更新/デメリット」を h2・h3 に反映
4. **FAQセクション 3〜5問** — 構造化データを意識した固定HTML形式
5. **リンク設計** — 外部（公的機関）1本以上／内部2本以上、アンカーテキストは内容が分かる語
6. **CTR設計** — タイトルに数字を必須化、メタディスクリプションに数字とベネフィット
7. **読了率設計** — 「この記事で分かること」3項目、表1つ以上、1段落2〜3文

### アイキャッチ画像の自動生成
- 1200×630（OGP準拠）のPNGをタイトルとフォーカスKWから生成
- Pillow で描画。日本語フォントは複数候補を順に探索
- WordPress メディアにアップロード → `alt_text` にフォーカスKWを設定 → `featured_media` に紐付け
- **生成に失敗しても記事作成は止めない**。未設定の理由を報告する
- QA側は「未設定のときだけ」生成する（既存画像は差し替えない）
- デザインの正本は `../scripts/make_eyecatch.py`

## 認証情報の扱い

ルーティンのプロンプト内に WordPress のアプリパスワードが平文で保存されている。
このリポジトリには**伏せ字でのみ**記録し、実物はコミットしないこと。

**推奨**: WordPress 管理画面（ユーザー → プロフィール → アプリケーションパスワード）で
`largo-office` のアプリパスワードを再発行し、ルーティン側の値を差し替える。
旧パスワードは失効させる。

## プロンプト正本

- `npo-largo-daily-post.md`
- `npo-largo-seo-qa.md`

いずれも `{WP_APP_PASSWORD}` の箇所に実際のアプリパスワードを入れて使う。
